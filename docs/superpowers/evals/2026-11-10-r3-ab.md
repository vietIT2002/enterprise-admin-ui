# R3 A/B: released skill vs candidate (2026-11-10)

**Question.** Does the candidate stop agents from adding capabilities the product cannot back, without making existing-layout work, review-only work or new screens any worse?

**Versions**
- **Old:** the released skill, `main` at `3a0e86f`, extracted with `git archive`.
- **New:** branch `fix/r3-rule-categories` at `1a01289`.

**Harness**
- Scenarios, pass criteria and grading are in `tests/agent-eval/r3/scenarios.md`.
- Every run uses the same run prompt, verbatim, with only `{PROJECT_DIR}` and `{SKILL_DIR}` differing.
- Every agent is a subagent on sonnet. Each gets a fresh copy of its fixture in a temp folder outside the repo, and its skill copy also sits outside the repo, under neutral names (`k1`, `k2`, `w01`…`w10`).
- S4 pages are graded with the branch's `audit-cli.mjs --type list --states --checks --disposable`.

## Result

| Scenario | Old (main) | New (candidate) |
|---|---|---|
| S1 existing layout: add a Status filter | **Pass** | **Pass** |
| S2 no draft support: build a 4-section create-order form | **Fail** | **Pass** |
| S3 review only | **Pass** | **Pass** |
| S4 new list page, run 1 | 100/100 | 100/100 |
| S4 new list page, run 2 | 100/100 | 100/100 |

**Ship decision: ship.** The candidate passes S1–S3, and S4 is no worse. Details:
- Both S4 versions score 100.
- Neither version has a `table-row-two-line` or `table-row-height` violation.
- `--states` passes on every run.
- The export check passes on every run.
- Confirm was skipped on every run, for the same reason in both versions (see S4).

The baseline changed the scope. The old skill already passed S1 and S3, because `DESIGN.md` steered it. So the user narrowed R3 to the failure the baseline showed (S2): Save draft becomes an optional capability, and there is a capability check before workflow actions. The precedence, Required/Defaults and review-label changes in the original design were not made. See the spec's "Scope after baseline".

## Caveats

- There is one run per cell for S1–S3 and two for S4, with one agent model (sonnet). This is a signal, not a measurement.
- Only the negative direction was tested. No scenario has a product that does store drafts, so "such a product still gets Save draft" rests on reading the text.
- The new-screen guard (S4) is a list page only, while the change acts on forms and workflow actions. Whether a new mock-data form keeps subtotal, tax and total (form step 2) under "never invent ... calculations" was not tested (S2-new dropped tax on a real product, which is right there).
- The author wrote the scenarios, and the controller that ran the evaluation also graded it. The grading criteria were fixed in `scenarios.md` before the baseline, and the quotes above are the evidence for each verdict.
- S1 and S3 test conventions recorded in `DESIGN.md`. This evaluation does not cover a project that has established conventions in code but no `DESIGN.md`.
- The S4 audit cannot see whether a page invents capabilities. Both S4 versions invented order statuses, including "Draft", for a brief that named none. That is expected for a new screen with mock data, and the capability rule does not forbid it.
